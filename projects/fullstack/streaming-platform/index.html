STREAMING PLATFORM

PROJECT OUTLINE

Goals

  • Recreate the core UX of a music streaming service entirely in the browser.
  • Success metric: browse, queue, and play tracks with under 200ms UI response.
  • Primary users: developers studying streaming UX patterns and music fans.

Scope

  • Genre browsing with artist and album cards.
  • Queue management with shuffle, repeat, and skip controls.
  • Audio visualizer and now-playing bar with progress scrubbing.

Architecture

  • Web Audio API powers the visualizer and audio routing graph.
  • Vanilla JS track store with playlist state managed in memory.
  • CSS animations and Canvas for the frequency-bar visualizer.

Milestones

  • Design track schema and player state machine.
  • Build genre browser, track list, and playback controls.
  • Add queue management, visualizer, and keyboard media-key support.

Risks

  • Autoplay policy blocking audio on first user interaction.
  • Web Audio context limits on mobile browsers.
  • Canvas visualizer dropping frames on low-end devices.

Next Steps

  • Integrate a real audio streaming backend (Cloudflare R2 + signed URLs).
  • Add user playlists, collaborative queues, and lyrics sync.
  • Plan v1.1: podcast support and offline listening via Service Worker.
